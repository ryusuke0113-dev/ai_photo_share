# 写真共有アプリ 要件定義書

## 1. アプリの概要

友人同士で、旅行や日常の写真を見せ合うためのインスタグラム風 Web アプリです。
ログインしたユーザーが「写真1枚 + 短いキャプション」を投稿し、投稿は一覧ページで誰でも見ることができます。

| 項目 | 内容 |
| --- | --- |
| 使用技術 | Python / Flask / Peewee |
| データベース | SQLite（開発用） |
| 画面 | Flask のテンプレート（Jinja2）で HTML を返す |
| 動作環境 | 自分の PC 上での開発・動作確認（ローカル環境） |

## 2. 想定ユーザー

- 友人同士で、旅行や日常の写真を見せ合いたい人
- 利用者は少人数（友人グループ程度）を想定する

### ユーザーの種類

| 種類 | できること |
| --- | --- |
| ログインしていない人（閲覧者） | 投稿一覧を見る、ユーザー登録する、ログインする |
| ログインしている人（会員） | 上記に加えて、写真を投稿する、自分の投稿を削除する、ログアウトする、（いいねする） |

## 3. 必須機能

初学者が1つずつ実装・確認できるように、機能を小さく分けています。
**上から順番に実装する**ことを想定しています。

### 3.1 ユーザー登録

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-01 | 登録画面の表示 | メールアドレス・表示名・パスワードの入力フォームを表示する |
| F-02 | ユーザーの保存 | 入力内容をデータベースに保存する（パスワードはハッシュ化して保存） |
| F-03 | 入力チェック | 未入力の項目がある場合はエラーメッセージを表示する |
| F-04 | 重複チェック | 登録済みのメールアドレスでは登録できないようにする |

### 3.2 ログイン・ログアウト

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-05 | ログイン画面の表示 | メールアドレス・パスワードの入力フォームを表示する |
| F-06 | ログイン処理 | メールアドレスとパスワードが正しければログイン状態にする |
| F-07 | ログイン失敗時の表示 | 間違っている場合はエラーメッセージを表示する |
| F-08 | ログアウト | ログイン状態を解除し、一覧ページに戻る |
| F-09 | ログイン状態の表示 | 画面上部に、ログイン中は表示名と「投稿」「ログアウト」、未ログイン時は「登録」「ログイン」を表示する |

### 3.3 写真投稿

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-10 | 投稿画面の表示 | 写真ファイルの選択欄とキャプションの入力欄を表示する（ログイン必須） |
| F-11 | 写真の保存 | アップロードされた写真をサーバーのフォルダに保存する |
| F-12 | 投稿の保存 | 写真のファイル名・キャプション・投稿者・投稿日時をデータベースに保存する |
| F-13 | ファイルのチェック | JPG・PNG 以外、または 5MB を超えるファイルはエラーにする |
| F-14 | 未ログイン時の制限 | ログインしていない人が投稿画面にアクセスしたら、ログイン画面へ移動させる |

### 3.4 投稿一覧

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-15 | 一覧の表示 | すべての投稿を新しい順に表示する（ログイン不要） |
| F-16 | 表示する項目 | 写真・キャプション・投稿者の表示名・投稿日時 |
| F-17 | 投稿がない場合 | 「まだ投稿がありません」と表示する |

### 3.5 投稿の削除

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-18 | 削除ボタンの表示 | 自分の投稿にだけ「削除」ボタンを表示する |
| F-19 | 削除処理 | 投稿をデータベースから削除し、保存した写真ファイルも削除する |
| F-20 | 他人の投稿の保護 | 他人の投稿は削除できないようにする（URL を直接入力された場合も含む） |

## 4. 余裕があれば追加する機能

必須機能がすべて完成してから取り組みます。

### 4.1 いいね

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-21 | いいねボタン | 一覧の各投稿に「いいね」ボタンを表示する（押せるのはログイン中のみ） |
| F-22 | いいねの保存 | 誰がどの投稿にいいねしたかをデータベースに保存する |
| F-23 | 1人1回の制限 | 同じ人が同じ投稿に2回いいねできないようにする |
| F-24 | いいねの取り消し | いいね済みの投稿でもう一度押すと取り消しになる |
| F-25 | いいね数の表示 | 各投稿のいいね数を表示する |

### 今回は作らない機能

以下は今回の対象外とします。

- コメント
- 投稿の編集（キャプションの変更など）
- 検索
- フォロー
- 写真の複数枚投稿

## 5. 非機能要件

| 分類 | 内容 |
| --- | --- |
| セキュリティ | パスワードは平文で保存せず、ハッシュ化して保存する |
| セキュリティ | ログインが必要なページは、未ログインではアクセスできないようにする |
| セキュリティ | 一覧画面などにメールアドレスを表示しない（表示名のみ表示する） |
| ファイル | アップロードできる写真は JPG・PNG のみ、1枚あたり 5MB まで |
| 入力制限 | キャプションは 140 文字まで |
| 表示 | 一覧は新しい投稿が上に来る順に表示する（ページ分けはしない） |
| 使いやすさ | エラーや成功の結果は、画面上にメッセージで表示する |
| 動作環境 | ローカル環境（自分の PC）で動けばよい。公開サーバーへのデプロイは今回は対象外 |

## 6. データの概要

実装時の参考として、必要なデータを示します（詳細な設計は別途行います）。

| データ | 主な項目 |
| --- | --- |
| ユーザー（User） | メールアドレス、表示名、パスワード（ハッシュ化済み）、登録日時 |
| 投稿（Post） | 投稿者（User）、写真のファイル名、キャプション、投稿日時 |
| いいね（Like）※余裕があれば | ユーザー（User）、投稿（Post）、いいねした日時 |

## 7. 実装時に注意すべきこと

### 7.1 進め方

- 必須機能（第3章）を上から順に1つずつ作り、ブラウザで動作確認してから次へ進む
- 1つの機能ができたら Git でコミットしておく（失敗しても戻れるようにする）
- いいね機能は、必須機能がすべて動いてから取り組む

### 7.2 パスワード・ログイン

- パスワードは `werkzeug.security` の `generate_password_hash` / `check_password_hash` を使ってハッシュ化・照合する
- ログイン状態の管理は、Flask の `session` または Flask-Login を使う
- `SECRET_KEY` を設定しないとセッションが使えない。また、本物のキーはソースコードに直接書かず、Git にも含めない

### 7.3 写真のアップロード

- ファイル名はユーザーが付けた名前をそのまま使わず、`uuid` などで重ならない名前に変更して保存する（同じ名前のファイルによる上書きや、危険なファイル名を防ぐため）
- 拡張子のチェック（JPG・PNG）はサーバー側で必ず行う
- Flask の `MAX_CONTENT_LENGTH` 設定で、5MB を超えるファイルを受け付けないようにする
- フォームには `enctype="multipart/form-data"` を付けないとファイルが送信されない
- アップロード先のフォルダ（例: `static/uploads/`）は `.gitignore` に追加し、写真を Git に含めない

### 7.4 データベース（Peewee）

- アプリ起動時にテーブルがなければ作成する（`create_tables`）
- メールアドレスは重複できないように `unique=True` を設定する
- 投稿一覧は投稿日時の新しい順（降順）で取得する
- いいね機能を作る場合は、「ユーザー + 投稿」の組み合わせが重複しないようにする
- データベースファイル（例: `*.db`）は `.gitignore` に追加する

### 7.5 削除処理

- 削除は GET ではなく POST で行う（リンクをクリックしただけで削除されるのを防ぐため）
- 削除する前に「ログイン中のユーザーが、その投稿の投稿者か」をサーバー側で確認する
- データベースの投稿を消すときは、保存した写真ファイルも一緒に削除する
